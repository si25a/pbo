## Soal 1 — Konsep Procedural Programming

Jelaskan pengertian procedural programming dan bagaimana data dikelola pada pendekatan tersebut.

**Jawaban:**
**Procedural Programming (Pemrograman Prosedural)** adalah paradigma pemrograman yang berfokus pada penyelesaian masalah melalui serangkaian langkah terurut atau urutan instruksi linier yang dikelompokkan ke dalam prosedur atau fungsi (*function*).

**Pengelolaan Data:**
Pada pendekatan prosedural, data dipisahkan secara tegas dari fungsi/prosedur yang memanipulasinya. Data biasanya disimpan dalam struktur data sederhana (seperti variabel global, tuple, list, atau dictionary) dan dilewatkan dari satu fungsi ke fungsi lain sebagai argumen/parameter. Tidak ada proteksi bawaan atau pembungkusan internal pada data, sehingga data dapat diakses atau diubah oleh fungsi apa pun yang memiliki akses ke variabel tersebut.

## Soal 2 — Perbedaan Pendekatan

Jelaskan perbedaan utama antara procedural programming dan OOP dalam hal penyimpanan data dan pengorganisasian kode.

**Jawaban:**

| Aspek | Procedural Programming | Object-Oriented Programming (OOP) |
| :--- | :--- | :--- |
| **Penyimpanan Data** | Data disimpan secara terpisah dari logika program (misal: variabel/dictionary mentah) dan dikirim antar fungsi sebagai parameter. | Data disimpan di dalam atribut *object* (terenkapsulasi), aman dari akses luar yang tidak sah. |
| **Pengorganisasian Kode** | Kode diorganisasikan berdasarkan **aliran fungsi/prosedur** yang melakukan operasi bertahap (*top-down approach*). | Kode diorganisasikan berdasarkan **objek dunia nyata** yang menggabungkan data (atribut) dan perilaku (method) menjadi satu kesatuan class. |

## Soal 3 — Analisis Kode (20 poin)

Perhatikan kode berikut:

```python
buku = {"judul": "Pemrograman Python", "tersedia": True}


def pinjam_buku(buku):
    if buku["tersedia"]:
        buku["tersedia"] = False
        return True
    return False
```

Identifikasi **pendekatan yang digunakan** pada kode tersebut dan jelaskan **alasan teknisnya**.

**Jawaban:**
**Pendekatan yang digunakan:** **Procedural Programming (Pemrograman Prosedural)**.

**Alasan Teknis:**
1. **Pemisahan Data dan Logika:** Data disimpan dalam bentuk struktur data terpisah (*dictionary* mentah `buku`), sementara operasi manipulasi data berada di dalam fungsi independen di luar data tersebut (`pinjam_buku()`).
2. **Tidak Ada Enkapsulasi:** Tidak terdapat definisi *class* atau pembungkusan atribut. Fungsi `pinjam_buku()` secara langsung mengakses dan mengubah *key* dictionary `buku["tersedia"]` tanpa ada kontrol akses (getter/setter atau validasi internal).

## Soal 4 — Kapan Menggunakan OOP (20 poin)

Sistem Informasi perpustakaan akan dikembangkan dengan menambah jenis koleksi baru dan jenis pengguna baru. Jelaskan mengapa OOP lebih tepat digunakan untuk kebutuhan tersebut.

**Jawaban:**
OOP jauh lebih tepat digunakan karena memiliki keunggulan utama dalam **skalabilitas dan pemeliharaan kode (*maintainability*)**:

1. **Pemanfaatan Inheritance (Pewarisan):** Ketika menambah jenis koleksi baru (misal: `BukuDigital`, `Jurnal`, `AudioBook`), kita cukup membuat subclass dari class induk `Koleksi`. Atribut umum (judul, penerbit) tidak perlu ditulis ulang. Hal yang sama berlaku untuk jenis pengguna baru (`Mahasiswa`, `Dosen`, `Peneliti`) yang mewarisi class `Pengguna`.
2. **Pemanfaatan Polymorphism:** Sistem perpustakaan dapat memanggil method yang sama seperti `hitung_denda()` atau `pinjam()` pada semua jenis pengguna/koleksi tanpa perlu mengubah struktur fungsi utama.
3. **Mencegah Side Effect:** Penambahan jenis koleksi/pengguna baru dapat dilakukan secara modular di dalam class baru tanpa merusak logika bisnis yang sudah berjalan pada class lama.

## Soal 5 — Analisis Kebutuhan (20 poin)

Tuliskan tiga pertanyaan analisis kebutuhan yang membantu menentukan apakah sebuah program sebaiknya menggunakan OOP atau procedural programming. Jelaskan jawaban yang mengarahkan pada OOP.

**Jawaban:**

**3 Pertanyaan Analisis Kebutuhan:**

1. *Apakah sistem mengelola entitas yang kompleks dengan atribut dan perilaku yang saling terikat erat?*
2. *Apakah sistem dirancang untuk berkembang dan bertambah fiturnya (skalabel) di masa depan?*
3. *Apakah terdapat banyak tipe data/pengguna yang memiliki kemiripan struktur namun butuh penanganan spesifik yang berbeda-beda?*

**Penjelasan Jawaban yang Mengarahkan pada OOP:**

* Jika jawabannya **"YA" untuk pertanyaan 1**: Mengarahkan pada OOP karena butuh *Encapsulation* untuk membungkus data dan perilaku menjadi satu objek yang aman.
* Jika jawabannya **"YA" untuk pertanyaan 2**: Mengarahkan pada OOP karena struktur modular membuat penambahan fitur baru di masa mendatang tidak akan merusak kode yang sudah ada (*Maintainability*).
* Jika jawabannya **"YA" untuk pertanyaan 3**: Mengarahkan pada OOP karena butuh fitur *Inheritance* dan *Polymorphism* untuk mengelola variasi entitas secara efisien dan konsisten.
