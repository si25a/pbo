## Soal 1 — Tujuan Encapsulation

Jelaskan tujuan encapsulation dalam OOP. Mengapa data tertentu perlu dikendalikan melalui method atau property?

**Jawaban:**
Tujuan utama dari **Encapsulation** adalah menyembunyikan detail implementasi internal dari suatu object dan melindungi data (attribute) dari akses maupun perubahan langsung yang tidak sah atau tidak valid dari luar class.

Data perlu dikendalikan melalui method atau property agar:
1. **Validasi Data:** Mencegah pengisian data yang tidak masuk akal (misalnya harga negatif, saldo bernilai minus, atau SKS bernilai non-angka).
2. **Keamanan & Kontrol Akses:** Memastikan logika bisnis tetap terpenuhi sebelum data diubah atau dibaca.
3. **Fleksibilitas & Kemudahan Pemeliharaan:** Jika struktur data internal berubah di kemudian hari, kode di luar class tidak akan rusak karena tetap mengakses interface (method/property) yang sama.

## Soal 2 — Private Attribute dan Property

Jelaskan fungsi nama attribute dengan awalan `__` dan peran decorator `@property` serta `@<nama>.setter`.

**Jawaban:**
* **Attribute dengan awalan `__` (Private Attribute):** 
  Berfungsi untuk mengaktifkan mekanisme *Name Mangling* pada Python, sehingga attribute tersebut tersembunyi dan tidak dapat diakses secara langsung dari luar class menggunakan nama aslinya (misalnya `obj.__attribute`).

* **Decorator `@property` (Getter):**
  Berfungsi mengubah suatu method menjadi *getter*, sehingga nilai dari private attribute dapat dibaca/diakses seperti halnya membaca attribute biasa (tanpa menggunakan tanda kurung `()`).

* **Decorator `@<nama>.setter` (Setter):**
  Berfungsi untuk mendefinisikan method *setter* yang dipanggil secara otomatis saat ada upaya mengubah nilai property (`obj.nama = nilai`). Di dalam setter inilah tempat menempatkan logika validasi sebelum data benar-benar disimpan ke private attribute.

## Soal 3 — Prediksi Output (20 poin)

Perhatikan kode berikut:

```python
class Mahasiswa:
    def __init__(self, nama, sks):
        self.nama = nama
        self.__sks = sks

    @property
    def sks(self):
        return self.__sks

mhs = Mahasiswa("Jhon Doe", 3)
print(mhs.sks)
```

Tuliskan **output** dan jelaskan **bagaimana property membaca private attribute**.

**Jawaban:**
Outputnya adalah:

```text
3
```

**Penjelasan:**
Saat perintah `mhs.sks` dijalankan, Python tidak mengakses attribute `__sks` secara langsung, melainkan secara otomatis mengeksekusi method `sks(self)` yang dihiasi oleh decorator `@property`. Method getter ini mengembalikan nilai dari private attribute `self.__sks` (yaitu `3`) kepada pemanggil. Dengan cara ini, akses ke variabel tersembunyi `__sks` dapat dilakukan dengan sintaks yang bersih seperti mengakses attribute biasa.

## Soal 4 — Validasi Setter (20 poin)

Lengkapi setter berikut agar nilai saldo negatif menghasilkan `ValueError`.

```python
class Rekening:
    def __init__(self, saldo):
        self.__saldo = 0
        self.saldo = saldo

    @property
    def saldo(self):
        pass

    @saldo.setter
    def saldo(self, nilai):
        pass
```

**Jawaban:**

**Kode yang sudah dilengkapi:**

```python
class Rekening:
    def __init__(self, saldo):
        self.__saldo = 0
        self.saldo = saldo  # Memanggil setter untuk validasi di awal

    @property
    def saldo(self):
        return self.__saldo

    @saldo.setter
    def saldo(self, nilai):
        if nilai < 0:
            raise ValueError("Saldo tidak boleh negatif!")
        self.__saldo = nilai


# Contoh pengujian:
rek = Rekening(100000)
print(rek.saldo)  # Output: 100000

# Mengubah saldo dengan nilai valid:
rek.saldo = 50000
print(rek.saldo)  # Output: 50000

# Mencoba mengisi saldo negatif (akan menghasilkan ValueError):
# rek.saldo = -20000  # Raises ValueError: Saldo tidak boleh negatif!
```

## Soal 5 — Analisis Access Control (20 poin)

Apa risiko jika attribute `saldo` dapat diubah langsung tanpa validasi? Berikan satu contoh aturan validasi yang sesuai untuk rekening mahasiswa.

**Jawaban:**
**Risiko jika attribute `saldo` dapat diubah langsung:**
1. **Integritas Data Rusak:** Saldo bisa bernilai negatif akibat kesalahan input manual dari luar (`rek.saldo = -50000`), yang secara finansial tidak logis.
2. **Kecurangan/Manipulasi Data:** Pihak luar bisa langsung menimpa atau menaikkan nilai saldo tanpa melalui prosedur pencatatan transaksi yang sah (tanpa pemanggilan fungsi setoran/tarikan).
3. **Bypass Aturan Bisnis:** Saldo dapat dikurangi melebihi batas saldo minimum yang harus tersisa di rekening.

**Contoh Aturan Validasi untuk Rekening Mahasiswa:**
Mengatur *saldo minimum yang mengendap* (misalnya Rp20.000). Saat penarikan atau pengubahan saldo dilakukan, sistem akan memeriksa apakah sisa saldo setelah transaksi tetap berada di atas atau sama dengan Rp20.000.

*Contoh logika pada setter:*
```python
@saldo.setter
def saldo(self, nilai):
    SALDO_MINIMUM = 20000
    if nilai < SALDO_MINIMUM:
        raise ValueError(f"Transaksi ditolak! Saldo minimum mengendap adalah Rp{SALDO_MINIMUM}")
    self.__saldo = nilai
```
